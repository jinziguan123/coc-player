# 工具调用提示与预算收尾优化提示词

请优化 coc-player 的 KP 工具调用行为：模型根据任务需要使用工具，由运行框架控制资源。

先阅读项目约定并检查 Git 状态。保留无关修改，所有回复与提交使用中文，验证通过后提交，不推送远端。

1. 排查 KP 系统提示、工具 schema、文本指令说明与工具返回消息中的预算措辞。移除提前告知模型的次数上限、节省调用等压力；保留业务限制、权限、检定门控、幂等与泄密约束。
2. 明确：必要查询应执行，不为节省调用而省略；状态变化必须经可用工具或兼容指令完成，叙述不等于执行；成功以工具结果为准，拒绝不能描写成完成；成功操作不重复。
3. 保持现有运行时硬预算、查阅配额与防重复机制数值不变，不扩大调用额度。额度拒绝时说明本次没有取得新资料，不得把拒绝当作成功，也不得编造缺失事实。
4. 工具循环耗尽时不额外请求模型编造收尾，由框架确定性暂停并明确已执行操作以记录为准、未执行操作未完成；保留已生成内容和已执行效果。总调用预算耗尽也应使用准确的暂停说明。
5. 用假 Provider 验证模型实际收到的提示/schema、硬上限仍有效、超限不再追加生成、拒绝结果回注、正常自然结束和待投骰挂起不受影响。运行后端全量 pytest、Ruff 和差异检查。
6. 不调用真实或付费 LLM。记录后续 A/B 验证方案：同模型、同输入、同硬预算，比较必要工具遗漏、状态与叙述不一致、重复无效调用、完成率及耗时费用；不得把离线测试通过表述为模型调用意愿已提升。
