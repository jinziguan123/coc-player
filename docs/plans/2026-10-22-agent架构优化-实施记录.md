## 1. 生命周期与取消

| 位置 | 行为 |
|---|---|
| `team_turn_service._run_team_turn` | 队友子任务统一在 `finally` 中 cancel + gather。父回合取消、生成器关闭、提交失败或超时，都等子任务全部退出后才继续 |
| `GenerationManager.start` | 回合包在 `call_budget.scope` 与 `asyncio.wait_for` 里。入口自己吞掉 CancelledError 正常返回时（`run_chat_generation` 就是这样），用剩余时间判断是否超时，补发系统提示和 `done`。task 首次调度前就被取消时，关闭原协程。done 回调先校验任务身份，旧任务结束不会清掉新任务的登记 |
| `HousekeepingManager` | `drain` 用 shield，取消等待者不会中断共享收尾；任务自身被取消与等待者被取消分开处理。`spawn` 时若旧任务未结束，新任务串在它后面执行，不会并发改写世界记忆，也不会覆盖登记让旧任务无人等待。done 回调及时读取异常（只记一次），并注销已完成任务 |
| `_failure_notice` | 预算超限单独给一句可行动提示，不再统一显示为「生成中断」 |
| 检定申请入口出错 | 错误提示改为落库，与其他入口一致；之前只广播，`done` 之后 resync 会把它抹掉 |

## 2. 效果通道（已迁 HP、理智结算、计划物品与规划器剧情标志）

- `services/effect_channel.py`：`HpChange` / `EffectProposal`。HP、重伤体质检定、事件、撤销信息与战斗态同步在一次短事务内提交，任一步失败全部回滚。嵌套调用都已核实为 `commit=False`：`event_store.add_event`、`character_service.change_conditions`、`combat_service._save_combat`、`_update_character_stat`。
- 自动来源（`kp_tool` / `kp_text` / `planner`）的去重键是「回合锚点 + 角色 + 数值 + 规范化理由」，来源本身不参与。这是**按完整参数的保守去重，不理解语义**：同轮同角色、同数值、同理由的两次真实伤害会被合并（已有测试固定这一边界），理由或数值不同则不会合并。
- 真人 KP（`manual`）的操作不做自动去重。
- 执行凭据写在 HP 事件的 `metadata.effect` 里，随重新生成一起回滚删除。
- `kp_actions` 遇到已在战斗或追逐中时不再重开，不会覆盖战斗态。

- **计划物品增减**（`ItemChange`）：每件物品一笔短事务，库存（`inventory_service` 新增 `commit=False`）、系统事件（`metadata.effect` 凭据）、`turn_state.item_delta_keys` 台账键同提交，中途失败整笔回滚。去重沿用既有键口径（`g|锚点|名字|角色` / `l|…`）；物品**不随**重新生成回滚，而是按键不重复增减，这一语义不变。暂存兑现（手动投骰、真人 KP 桌面、自动掷）走同一入口，且先摘掉暂存再逐件结算，结算失败不会在下次投骰时被重复兑现。玩家自己在物品栏的操作（使用/转让/编辑）不走通道。

- **规划器剧情标志**（`FlagChange`）：一次剧情推进里的全部置/清标志与 KP 专属推进记录同提交（`session_service.set_flag` 新增 `commit=False`），记录写入失败时标志全部回滚，不会出现「标志落了一半、没有推进记录」。场景状态配图在提交后只做一次（`turn_effects._after_flags_changed`）。幂等仍由白名单校验保证。KP 工具/文本的单个标志本来就是一次提交，未改动。

- **理智结算**（`SanChange`）：`_settle_san_target` 的 SAN 数值、疯狂状态、骰子事件与恐怖源台账（`session_ledger.san_checked` + `turn_state.san_turn.settled`）同一次提交，此前是 4 次独立提交，中途失败会「SAN 已扣、台账没记，重新生成再扣一次」。重生成抵扣（credit）与记账也合成一次提交。SAN 仍沿用「不回滚、按台账与 credit 抵扣」的既有模型，去重逻辑未改。
  - 玩家点投骰的 SAN 卡：待投卡的消费并入同一笔事务，并**提前到排空后台收尾之前**（只写角色卡、台账与 turn_state，后台收尾只写 world_state，不冲突）。失败时卡仍在、可重投；重复点击时第二次视为重复、不再扣。**行为变化**：此前结算在排空前、消费在排空后，中间失败会留下「已扣 SAN 的卡仍可再投」。
  - 执行凭据只落库（`metadata.effect`），不随骰子广播下发；重连拉历史时会随事件元数据返回，其中的恐怖源键与待投卡上已公开的 `san_key` 相同，没有新增暴露。

- **普通技能检定投骰**：骰子事件与消费待投卡用 `effect_channel.transaction` 同一笔提交，并提前到排空后台收尾之前（卡在 turn_state，收尾只写 world_state）。**行为变化 / 修复**：此前骰子事件先提交、卡在排空之后才消费，中途失败（含排空本身失败）会留下「骰子已出、卡还能再投」，玩家可借此重掷更好的结果。
- **场景切换**：主角与随行队友的位置写入（`navigation_service.set_char_location` 新增 `commit=False`）同一笔事务，失败时整队不动，不会「主角到了、队友留在原地」。随行名单改为移动前一次算定，结果与原先逐个判断等价。场景配图仍在提交之后。

- **开战**：复核后不另迁。`combat_service.start_combat` 写战斗态本来就是一次提交；随后的敌方先手与开场旁白属于战斗服务内部（草案已将 `CombatAgent` 叙事划为边界）。重复提案由 `kp_actions` 的「已在战斗中不再开」保证幂等。

- **权威登记表**（`effect_channel.AUTHORITY`）：每类效果载荷登记允许的来源、去重口径与重新生成时的处理；新增载荷必须登记，否则测试失败。这是草案「权威表」的声明式落地。**没有**做成统一台账：各效果的去重口径本质不同（HP 可撤销、物品与 SAN 不回滚而按台账抵扣、标志靠白名单），强行合一会改变既有语义，故只统一登记与事务边界。

## 3. 叙事流水线

- `services/turn_pipeline.py`：`NarrationResult`、`TurnSpec`、`TurnContext` 与 `run()`。常规工具路径和文本路径、`_run_kp_turn` 两条路径、分头工具路径和文本路径、尾声，都走 `_run_narration_stage`。
- **兼容接口**：`NarrationResult` 保留位置下标（`r[0]` 旁白、`r[1]` 指令原文、`r[2]` 气泡、`r[3]` 台词偏移、`r[4]` 分组偏移），支持负下标、切片读取、`r[i] = v`、`r[0] += s`、解包和迭代；不支持 `del r[i:]`（唯一调用点已改用 `clear_presentation`）。旧解析器和插件按 `len(result) > k` 判断的写法照常可用。
- 失败语义：取消、断流或校验失败时保存半截产物；这次保存若再失败，只记日志，向上抛的仍是最初的异常。正常落库失败直接上抛，不重试，避免旁白提交两次。
- 检定缓冲和高风险缓冲中**尚未放出**的旁白，取消或出错时不写进存档。
- `finish=False`：常规回合的旅行建议、战斗余波清理 `combat_result`，现在都在 `done` 和后台收尾启动之前完成。
- **叙事前效果阶段**：`PRE_EFFECT_ORDER` / `PRE_ENTRY_EFFECTS` 与 `TurnSpec.pre_effects`；目前唯一一项 `gated_items`（规划器识别出检定申请时先暂存门控收获），由 `_run_pre_effects` 执行。
- **续写出口**：曾把文本路径的投骰续写与查阅续写统一到 `turn_pipeline.stream_stage`；随后整条旧文本路径删除（见下），这些出口一并消失——续写现在只发生在工具循环内（工具结果回注后继续生成），走的是同一个 `_run_narration_stage`。`stream_stage` 作为生成器出口的通用阶段保留并有契约测试。
- **文本指令适配层**（`app/ai/text_tool_adapter.py`，草案 7.6）：把纯文本 Provider 包成支持工具的 Provider——照常流式吐文本，生成结束把全部终止型指令解析成 `tool_call` 增量，工具结果在下一轮改写成带前缀的普通消息回注；不追加「工具调用模式」提示。经第 8 节真实模型评测与旧路径持平后，**成为不支持原生工具（或关了工具调用）时的唯一路径**。续写语义与旧路径对齐（评测中发现并修正）：只有检定与查阅结果才让模型续写，场景/开战/标志等状态指令执行完本轮即结束；检定与查阅结果本身就是执行器写好的续写提示（`KP_DICE_/RULE_/MODULE_CONTINUATION_PROMPT`），原样回注、不加前缀（删除旧路径时发现上一版会对检定结果二次套用续写提示，已修正）；其余工具结果带「【系统执行结果】」前缀。文本里的查阅指令是终止性的：同段其后的指令不执行，等查阅结果回来由模型重新决定（与旧路径约定一致）。双路径等价测试新增第三条腿（适配层 vs 原生工具，9 组意图逐步快照一致）与端到端用例。
- **修复**：分头工具循环此前漏了「工具调用模式」提示（单场景路径有），模型可能继续写文本指令、每步只被兜底解析第一条；已补齐。
- **删除旧文本路径**（2026-10-23，房主要求）：删去 `_process_commands`、`_handle_rule_lookup` / `_handle_module_lookup` / `_handle_recall_history`、`_continuation_narration`、`_group_scope_resolver` / `_group_label_for_text`、`_run_split_narrations`，以及常规回合、分头回合、旁路回合里的旧分支与 `text_commands_via_adapter` 开关；`kp_tool_loop.loop_llm` 只在「原生工具」与「文本指令适配层」之间选择。玩家申请检定的兜底补挂改为经同一执行器执行（分头时限定在触发者那一组并打组标签）。分头回合原先还有一套手写的后置守卫，此次一并改用 `_run_post_effects`（常规口径），回合挂起规则也就对分头生效。`kp_tool_loop.py` 1419 → 914 行。
  - 测试：新增 `tests/text_commands.py`（`run_text_commands` 用适配层同款解析器 + 真实执行器执行文本指令；`loop_from_stream_fake` / `scripted_kp_loop` 作工具循环替身）。原先直接调用旧函数的约 40 处用例改到执行器/工具循环上；只测已删除内部函数的用例（合并文本的组界解析、旧分头续写打组标签、旧查阅续写落库）删除或改写为执行器口径（按组 `dice_scope`、查阅结果回注、配额共享）。

- **后置效果统一编排**：`turn_pipeline.POST_EFFECT_ORDER` 规定唯一顺序（计划开战 → 补开战 → 申请检定兜底 → 场景 → 进场检定 → SAN → 反噬 → 物品 → 范围伤害 → 剧情标志 → 叙事记账），`ENTRY_EFFECTS` 声明各入口允许的子集并写明理由，入口经 `TurnSpec.for_entry(...)` 取得：`regular`（常规回合、重新生成、开场）、`side`（投骰续写、检定申请、前往、战斗余波、幸运决策）。两类入口都走 `turn_orchestrator._run_post_effects`，回合挂起规则（第 6 节 #5）也就对旁路续写同样生效。旁路的叙事后规划改为懒执行：在第一个依赖计划的效果之前才跑。**行为变化**：旁路里剧情标志从 SAN/反噬之前挪到之后，与常规回合一致；玩家申请检定的兜底补挂从全部守卫之后提前到挂起判定之前，补挂出的检定会让进场检定/门控场景与 SAN 让路，不再与之叠卡。

**未统一**：旁路之后的队友回合仍在入口内手写。

## 4. 预算与上下文

- `ai/call_budget.py`：一次生成共享一本账，子任务（队友并发决策）继承。在 OpenAI 兼容和 Anthropic 的 `complete` / `stream` / `stream_chat` 调用前预占次数；`usage_tracker.add` 累计真实 token；预算紧张时跳过 `style_editor` 的可选润色。
- 配置（`app/config.py`，均可用环境变量覆盖）：

  | 键 | 默认 | 说明 |
  |---|---|---|
  | `generation_max_seconds` | 600 | 回合总时限 |
  | `generation_max_calls` | 48 | 按逻辑 Provider 调用计，**不含** Provider 内部的 HTTP 重试 |
  | `generation_max_tokens` | 500000 | 供应商返回 usage 后才累计，只能拦住**后续**请求，**不是计费硬上限** |
  | `housekeeping_max_seconds` | 90 | 后台收尾时限，收尾另用 12 次 / 10 万 token 的独立预算 |

- **不继承回合预算的后台任务**：配图（`_spawn_illustration`、手书配图）用 `call_budget.detached` 启动；后台收尾自建预算；素材解析等生成之外的请求不在任何预算作用域里，不受影响。
- `ai/token_estimate.py`：KP 上下文与 `ContextBundle` 共用同一估算口径。
- `ContextBundle.fit`：始终保留系统消息（包括出现在中途的）、末组消息，以及**最后一条玩家输入**（工具续写轮的末组是工具交互，玩家输入在它前面）；工具调用与其返回结果成组裁剪。必须保留的内容仍超预算时抛 `ContextBudgetExceeded`，不静默截断。Planner 的裁剪放在 `run_turn_planner` 的 try 内，超预算时降级为无计划。

## 5. 后台收尾的快照校验

`services/housekeeping_snapshot.Snapshot`：等待模型前记下 world_state、当前场景、事件尾序号，以及尾序号之前全部事件的摘要；模型返回后重新读库比对。

- `allow_append=True`（滚动摘要、幕后推演、章节合并都用这一档）：只允许尾部**追加**新事件。摘要和推演针对的是旧区间，新事件留给下一轮；旧区间内有事件被删改（如重新生成回滚）、world_state 变化、场景变化，都视为过期，整份结果丢弃，游标不动，下轮重试。
- 默认档（`allow_append=False`）更严格，新事件也视为过期。
- 章节合并：校验通过后基于**刷新后**的 world_state 构建，不写回等待前的副本。
- 滚动摘要的 NPC、线索、队友记忆差量，改为与新章节、游标**在同一次提交里**落库，不再拖到章节合并的模型等待之后；差量合并失败时只丢差量，摘要照常推进。
- 已有接线测试：在模型等待期间用另一个数据库会话写入，验证旧摘要、合并结果、幕后推演都不会覆盖新局面（`tests/test_housekeeping_staleness.py`；去掉校验后其中 5 个用例会失败）。

| # | 草案描述 | 复核结论与处理 |
|---|---|---|
| 1 | 排空收尾吞取消 | 属实，已修（第 1 节） |
| 2 | 主路径漏传 `pre_gen_seq` | 属实，已修 |
| 3 | planner 识别出检定申请后丢弃 plan | 属实。现在进入检定申请分支前，计划里被检定门控的收获先暂存（线索原本就会暂存），失去/消耗照常结算；场景、SAN、flag 依赖检定结果，**刻意不提前执行**，交给投骰后的续写（它会现跑 planner） |

| 6 | `done` 之后仍写 world_state | 属实，见第 3 节 `finish` |
| 7 | 开战/开追逐不查是否已激活 | 属实，已修 |
| 8 | KP 的 `set_flag` 不过白名单 | 属实。KP 工具和文本指令统一过 `plot_progress.model_flag_rejection`：只认模组钩子的 set/clear 标志，以及实体 `states[].when` 引用的标志；清除只回收已激活的标志。被拒时工具结果告知 KP。规划器仍走原有白名单，**真人 KP 不受影响** |
| 9 | NPC 意图前置不满足仍记入账本 | 属实。前置不成立时只生成台词，不写对象账本，世界意图也只记为对话 |

## 7. 高风险叙事的展示边界

普通回合**照旧流式**，终检只能修订存档，**已播出的内容收不回**（已有测试固定这一既有限制）。

规划器给出 `safety.do_not_reveal` 的回合改为缓冲：

- 生成期间不推流，只发一条「守秘人正在斟酌措辞…」状态；终检完成后再放出。
- 终检**改写**了旁白时，按长度比例把改写稿切回原来各个非旁白事件（台词、骰子、工具卡）之间，**保住交错顺序**，不会整段替换后把气泡全挤到一起。展示版本与存档版本一致（含润色）。
- 终检**不可用、超时、异常或判违规却没给改写稿**，按 `narration_buffer_on_failure` 处理：
  - `release`（默认）：放出**未经校验**的原文，保持可玩。**这不保证不泄密**，日志会明确记录。
  - `withhold`：清掉旁白和台词，换成占位旁白提示重新生成；骰子等工具卡照常显示。保密优先，代价是这段叙述丢失。
- 缓冲期间取消：什么都不展示，未校验的旁白也不落库。
- 配置：`narration_buffer_high_risk`（默认 true；设为 false 恢复全程流式）、`narration_buffer_timeout_seconds`（默认 60）、`narration_buffer_on_failure`。
- 为了区分「通过」和「没校验成」，`turn_validator.validate_turn_narration` 新增可选参数 `report`；不传时行为不变。

**取舍与未验证项**：缓冲会拉长这类回合的首字延迟（等于整段生成加一次终检）。`do_not_reveal` 还会被最近的幕后事件填充，实际有多少回合会触发缓冲**没有用真实对局统计过**。如果体感太慢，可以关闭缓冲，或改为只在规划器自身给出 `do_not_reveal` 时触发。本轮**没有**改动提示词，也没有迁移裁定权。
