# 内置直连（P-Net-4b/4c）真机验证清单

> 代码已合入但**从未真的连通过一次**。本文是照着做的操作手册，跑完才能说功能可用。
> 设计见 [`2026-07-29-内置直连组网-design.md`](2026-07-29-内置直连组网-design.md)。

## 为什么必须真机

自动化测试覆盖的是反代逻辑（内存管道代替 QUIC 流）和纯函数。**完全没覆盖**：

- iroh 的连接建立、discovery、打洞、relay 降级；
- Tauri capability 是否真的放行了 IPC——`netlinkAvailable()` 在浏览器/vitest 里
  一律返回 false 走降级分支，**这条在浏览器里测不出来**，而它是 4c 全部界面的前提。

## 不需要什么

不需要公网 IP、云服务器、端口转发。两台躲在 NAT 后的普通电脑即可。

## 环境准备（两台都要）

用 `tauri dev` 而不是打包版——省掉 PyInstaller 与 tauri build，但仍是真 Tauri 窗口，
IPC 与打包版一致（capability 已放行 `http://localhost:*`）。

前置：Node + pnpm、Python venv、**Rust ≥ 1.91**（iroh 1.0 的要求，`rustup update`）。

> Windows 首次 `cargo` 编译要拉整棵 iroh 依赖树，十几到几十分钟，先跑起来再喝杯茶。

三个终端：

```bash
pnpm install
pnpm dev          # Windows 用 pnpm dev:win —— vite(5173) + uvicorn(8000)
```

```bash
pnpm tauri dev    # 真 Tauri 窗口，加载 http://localhost:5173
```

启动时这行是**正常的**，不是错误——后端由上面那个终端提供，不该由 Tauri 拉起：

```
[INFO] 开发模式：未找到后端 sidecar，跳过启动。请另开终端跑 pnpm dev（后端 8000）
```

## 分两轮

**第一轮：ZeroTier 开着。** 先排除网络因素，验证功能本身。此时 iroh 多半会走
ZeroTier 的虚拟网段直连，测不出真实穿透，但下面 1–9 条都能验。

**第二轮：两边都关掉 ZeroTier。** 这才是真实的 NAT 对 NAT，验证第 10 条。

---

## 清单

设置页 →「联机」→「内置直连」。

### 1. IPC 是否放行（**最关键，其余全部依赖它**）

打开设置页，若显示「此功能只在桌面版可用」——**capability 没生效，后面都免谈**，
把整段文字和浏览器控制台的报错发我。正常应看到带开关的面板。

### 2. 开启并拿到邀请码

房主侧打开开关 → 不应提示重启 → 填房间码（可留空）→「生成并复制邀请码」，
应得到 `trpg:xxxxx:ROOMCODE` 形式的一串。

### 3. 陌生人敲门与批准

客人侧「加入房间」的主机地址栏**粘贴整串邀请码**（不是 IP），点加入。

- 房主侧应在两秒内冒出待批准项；
- 客人侧此时**卡着等待**而不是立刻失败；
- 房主点同意后，客人**不需要重连**就该进得去。

若房主两分钟不理会，客人侧应断开。

### 4. 开团与 SSE

进房开团，观察消息是否持续推送。**卡顿或整段不动**说明反代缓冲了响应体，
是硬伤，要立刻报。

### 5. 客人拿不到房主的 AI 配置（安全项）

客人侧打开「设置 → AI 配置」，应当是**客人自己机器上的配置**，
且任何写操作都应 403。若看到房主的 API key——**立即停止验证**，隧道标记没生效。

### 6. 限速按公钥分桶（安全项）

客人侧反复输错房间码十几次，应被限速（429）。若无限次不受限，
说明客人被当成了房主本机。

### 7. 席位保留

客人退出应用、重开、再用同一邀请码进来——**席位应该还在**，
不该变成一个新玩家。这条验的是 token 按房主公钥而非按本地端口归属。

### 8. 名册记住了朋友

客人第二次连入**不应再需要房主批准**（名册跨重启保留）。
房主重启应用后再试一次，仍不该需要批准。

### 9. 吊销

房主在「已允许的朋友」里移出该客人 → 客人当前连接**不会**立刻断
（已知限制，名册只在建立连接时查一次）→ 客人断开重连后应被挡住。

### 10. 真实 NAT 穿透（第二轮，关掉 ZeroTier）

两边都关掉 ZeroTier 后重复第 3 步。连得上即穿透成功。
留意首次连接耗时——明显偏慢说明打洞失败、走了 relay（境外节点）。

Windows 首次运行可能弹防火墙授权框，**需要允许**，否则 UDP 被挡死只能走 relay。

## 出问题要给我什么

- 卡在哪一条、界面上的原文提示；
- 房主与客人两侧 `pnpm tauri dev` 终端的输出（隧道的日志走 `log::` 打在那里，
  含「陌生对端请求接入」「直连客人接入/断开」「转发到本机后端失败」等）；
- 浏览器控制台报错（Tauri 窗口里右键→检查）。
