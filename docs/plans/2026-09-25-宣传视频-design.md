# 宣传视频设计稿

> 2026-09-25。给 B 站跑团玩家看的 2 分钟宣传片：萌系「哈基米」旁白 × 克苏鲁悬疑的真实对局画面。
> 整支片子由代码生成（Remotion）；对局素材走「真模型录一次磁带、之后反复回放录屏」；
> 作者只在五个节点审片。

## 1. 目标与前提

- **目标**：吸引中文跑团玩家下载试玩。看完的人应当知道三件事：它能做什么（AI 当 KP、一个人也能开团、
  叫朋友联机、自己当 KP 时 AI 打下手）；门槛是什么（自备模型接口，数据留在本机）；去哪下载。
- **前提：先出包，再发视频**。目前 GitHub 上没有 Release，介绍页 `site/index.html` 的
  `COC_DOWNLOADS` 链接为空。视频可以并行制作，但必须等安装包上线、下载链接填好后才能发布，
  否则视频带来的人会在介绍页上流失。出包另案处理，不在本设计范围内。
- **平台**：B 站横屏 16:9，约 2 分钟，4K60 导出，字幕烧进画面。分区投「人工智能」，因为 2025 年
  改版后已经没有「桌游棋牌」「软件应用」这两个子分区，同类 AI 跑团视频也都投在「人工智能」。

## 2. 已定决策

| 事项 | 决定 | 备注 |
|---|---|---|
| 用途 | 吸引跑团玩家 | 不是作品集，也不是开发者宣传 |
| 发布顺序 | 先出安装包，再发视频 | 视频制作不必等 |
| 平台与时长 | B 站横屏，约 2 分钟 | 调研建议 60–90 秒，作者定 2 分钟 |
| 叙事结构 | 痛点开场 → 一局团缩影 → 功能快剪 → 门槛 → 结尾 | |
| 旁白 | 哈基米梗的萌系声线，走反差路线 | 不用梗的原声，见 §5 |
| 制作方式 | 全自动，作者只审片 | |
| 对局素材 | 录一次磁带，之后反复回放 | 见 §4.3 |
| 商标 | 视频照做，项目名另行评估 | 管线支持改名后低成本重录 |

## 3. 内容设计

### 3.1 哈基米人设

- 设定是「一只想跑团的猫」，名字就叫哈基米。这个梗词本身可以用。
- 头像用 game-icons 的 `GiCat` 矢量图标，遵守仓库「图标不用 emoji」的规矩；转场、强调等其他图形
  也只用 game-icons（`GiPawPrint`、`GiRollingDices`、`GiLighthouse`、`GiBrainTentacle` 等）。
  哈基米说话时头像轻轻晃动，台词用萌系花字显示。
- 声音用有授权的萌系音色逐句合成，句子之间穿插 CC0 授权的猫叫音效。
- **反差**：对局画面里 AI 写的叙事保持原样的悬疑恐怖，哈基米只在画外吐槽和串场；配乐在「萌」
  和「恐怖」两套之间硬切换。

### 3.2 分镜（120 秒）

画面全部来自真实界面，只有哈基米、字幕、角标和片尾卡是后期叠加的。

| 时间 | 段落 | 画面 | 哈基米（示意，定稿见审片节点 1） |
|---|---|---|---|
| 0:00–0:06 | 钩子 | 灯塔底层盐画螺旋的叙事逐字浮现，3D 骰子落地，打出「理智检定 失败」 | 一声猫叫惨叫：「哈基米的理智……没了」 |
| 0:06–0:15 | 痛点 | 大厅里 KP 位和玩家位都空着；随后 KP 位换成 AI，空位坐上 AI 队友 | 「想跑团，没有 KP，还凑不齐人」 |
| 0:15–1:15 | 一局团缩影 | 港务所开场约 10 秒，侦查检定 8 秒，栈桥难度 7 秒，理智检定 8 秒，灯室战斗轮 14 秒（先攻、棋盘、攻击与闪避），退潮阶梯追逐 8 秒，黎明结局 5 秒 | 每幕一句，比如「KP 是 AI，骰子是程序掷的，它可不会偷偷改点数」 |
| 1:15–1:45 | 功能快剪 | 导入模组后 AI 解析成详情、关系图、时间线、沙盘四种视图，10 秒；车卡向导 7 秒；房间码联机 6 秒；真人 KP 工作台 7 秒 | 「自己的本子也能导」「朋友来了就联机」「想自己当 KP？AI 给你打下手」 |
| 1:45–1:55 | 门槛 | 设置页的 AI 配置，密钥打码 | 「先说好，要自己准备一个 AI 模型接口，数据都在你自己电脑上」 |
| 1:55–2:00 | 结尾 | 应用名、介绍页地址、「非官方」声明 | 「哈基米在灯塔等你」，再来一声猫叫 |

对局素材只来自原创示例团《雾港失灯事件》。它的六幕正好依次覆盖探索取证、检定难度、理智检定、
结构化战斗轮、追逐和结局（见 `server/app/content/onboarding.py`）。快剪里的导入演示用一个
为本片新写的原创小模组，不用任何商业模组。

### 3.3 文案口径

沿用介绍页的对外口径（`site/README.md`「页面文案的硬约束」）：

- 不说「完整实现 CoC 七版」，也不说「正式版」「正式发行版」；
- 门槛照实讲：要自备模型接口，数据留在本机；
- 片尾和简介写明「非官方，与 Chaosium 无隶属或背书关系」；
- 片中提到规则时只做描述性提及，例如「按《克苏鲁的呼唤》第七版规则」。

## 4. 技术管线

### 4.1 目录

```text
promo/
├── package.json        独立于 pnpm 工作区（不放进 apps/、packages/），CI 和日常安装都不必装 Remotion
├── harness/            后端外挂：磁带录制与回放、固定随机种子（Python，复用 server/.venv）
├── bot/                Playwright 脚本：玩家机器人（录磁带用）与导演脚本（录屏用）
├── script/             旁白稿 narration.yaml 与分镜时间锚点
├── src/                Remotion 合成工程
├── assets/ledger.yaml  授权台账（入库）；音频、字体文件本身不入库
├── tapes/              锁定后的磁带（入库：纯文本、体积小，换台机器也能复现）
└── .work/              干净库、录屏、配音、渲染产物（不入库）
```

### 4.2 流水线

| 命令 | 做什么 | 产物 |
|---|---|---|
| `promo:seed` | 在 `promo/.work/` 建干净库：原创示例团、预设调查员、导入演示用的原创小模组，以及大厅和真人 KP 镜头需要的房间；模型配置只从作者配置里复制选中的一条 | 干净库、`ai_settings.json`（不入库） |
| `promo:tape` | 挂上外挂，用**真模型**录制；玩家机器人跑完六幕，跑完自动检查剧情节点 | `tapes/*.jsonl` 与对局文字记录 |
| `promo:shoot` | 用同一个种子、同一串玩家操作，**回放磁带**并录屏；导出时间轴 | 录屏文件、`shots/*.json` |
| `promo:voice` | 旁白稿逐句合成，按「文本 + 音色 + 引擎」缓存 | 每句的 wav 和时长清单 |
| `promo:render` | Remotion 合成并渲染 4K60；同时出封面和简介 | 成片 MP4、封面 PNG、`description.md` |

「剧情节点检查」指：理智检定至少失败一次（钩子要用）、战斗轮和追逐都被触发、走到了结局幕。
不满足就换种子重跑。

### 4.3 磁带外挂（录一次，反复回放）

- **挂载方式**：`promo/harness/run_backend.py` 先导入 app，在 `app.ai.llm_factory` 创建模型的
  地方给每个 `LLMProvider` 套一层磁带包装，再设好 `random` 的种子，最后以编程方式启动 uvicorn。
  **应用代码零改动。**
- **包装的范围**：`LLMProvider` 的 `complete`、`stream`、`stream_chat`（含工具调用）、
  `complete_vision`，主模型和快模型都包。
- **录制模式**：调用透传给真模型，把输出（文本、工具调用）按顺序追加写进 JSONL。
- **回放模式**：按顺序取出对应的输出，不再请求模型。流式文本按设定速度切片吐出（字数每秒可调），
  规划器等非流式调用只停顿很短的时间。录屏里看不到「思考」的空档。
- **顺序键**：按「方法 + 系统提示词开头的摘要」分通道，每个通道内部按先后顺序对号。这样后台任务
  （如滚动剧情摘要）和主回合交错执行时也不会串位。会话 id、房间码这些每次都不同的值不参与对号。
- **骰子**：后端掷骰用的是标准库 `random`（`server/app/rules/dice.py` 等），种子固定、调用顺序
  一致，点数就一致。
- **对不上就报错**：回放时如果通道或调用次数对不上（比如之后改了回合编排逻辑），直接失败并提示
  重录磁带，不会悄悄录出错误的画面。只改界面不影响磁带，可以直接重新录屏。

### 4.4 录屏

- **目标规格**：视口 CSS 1920×1080，设备像素比 2，也就是物理 3840×2160，后期放大局部时不糊；
  暗夜哥特主题；关闭应用自带的音效，声音全部在后期加。
- **录制方式在实施第一步做技术验证后决定**。调研结论：macOS 上 Chrome 不支持逐帧确定性渲染
  （`beginFrame`），Playwright 的 `recordVideo` 画质不够（VP8、25fps、约 1Mbps），只能实时录。
  候选按优先级：
  1. Chrome 标签页采集（`getDisplayMedia` 选当前标签页 + `MediaRecorder` 高码率），不用装别的软件，
     也只录网页内容；
  2. OBS（ScreenCaptureKit 窗口采集，obs-websocket 自动控制开始和停止），需要作者给一次录屏授权。
- **降级**：如果 1920×1080@2x 做不到，就降到 1600×900@2x 或 1920×1080@1x，并相应限制后期的
  最大放大倍数。录屏帧率不够 60 也可以接受：推拉镜头、字幕这些由 Remotion 生成的动效照样是 60fps。
- **时间轴**：导演脚本记录关键事件的时间点、关键元素的位置框和每次点击的坐标，写进 `shots/*.json`。
  后期的推拉镜头和假光标都靠它。脚本操作不会移动系统光标，所以光标由 Remotion 画。

### 4.5 配音

- 引擎做成可替换的，先试音再定。候选有两个：
  - 本地 Qwen3-TTS（Apache-2.0，经 mlx-audio 在 Apple Silicon 上运行），可以用文字描述设计一个萌系音色；
  - 豆包语音 2.0 的预置音色（云端，需要作者开通账号，2 分钟旁白的费用在几分钱量级；只用预置音色，
    不用声音复刻）。
- 排除条件：非商用许可的模型；任何克隆特定真人或角色声音的做法。
- 对齐方式：逐句生成音频，由 Remotion 按每句的实际时长排时间轴。不依赖模型的时长控制参数。

### 4.6 合成（Remotion）

- 按 1920×1080、60fps 的坐标排版，渲染时 `--scale=2` 输出 3840×2160。录屏素材本身就是 4K，文字和
  矢量图形在放大后依然清晰。
- 组件：哈基米（`GiCat` 头像 + 花字台词）、带推拉镜头的录屏片段、假光标、「理智失败」特效
  （画面抖动 + 红闪）、片头 AI 角标、片尾卡、转场。
- 声音：配乐在旁白出现时自动压低音量；音效只用授权台账里登记过的文件。
- 配色和字体取自 `apps/web/src/index.css` 的主题变量，和应用保持一致。花字用 OFL 授权的开源字体。
- 实施时安装 Remotion 官方的 Agent Skills（`npx skills add remotion-dev/skills`），和仓库现有的
  `skills-lock.json` 管理方式一致。

### 4.7 自动校验

- 外挂：单测覆盖「录制后回放，输出一致」和「调用对不上时报错」两件事。
- 文案：旁白稿和简介过禁用词检查，包括 §3.3 的说法和 emoji。
- 成片：用 ffprobe 核对时长（约 120 秒）、分辨率（3840×2160）、帧率（60），并测量响度。
- 授权：用到的每个音频和字体都必须在 `ledger.yaml` 里有记录（来源、作者、许可、署名文本），
  否则拒绝渲染；简介里的署名由台账自动生成。

## 5. 合规与风险

- **AI 标识**：片头放角标「AI 合成配音｜对局叙事由 AI 生成」，至少停留 2 秒，字高不低于画面短边的
  5%（按 GB 45438-2025 的解读）。B 站投稿时勾选「该视频使用人工智能合成技术」，简介里也写明。
- **声音**：哈基米梗的原声来自《赛马娘》东海帝王的官方语音（声优 Machico），以及用这些语音训练的
  AI 克隆，没有任何授权渠道。2024 年北京互联网法院判过 AI 声音侵权；最高法 2026-09-07 的意见写明，
  未经同意生成可识别的人声属于侵权；B 站 2026-05 的公告点名要从严处置「AI 虚假配音」。
  所以只用预置音色或文字设计的音色，保留梗词和猫叫来致敬。
- **配乐、音效、字体**：
  - 配乐以 Incompetech（CC BY 4.0，简介署名）为主；Pixabay 作补充，只选没有 Content ID 盾牌标记的曲目。
  - 音效用 Freesound 和 Kenney 的 CC0 素材。
  - 不用 YouTube 音频库（没找到允许在 YouTube 以外使用的官方条款）、必剪曲库（限个人、非商业使用），
    也不用 NC、ND 许可的曲目。
- **画面内容**：只来自干净库；设置页的密钥打码；不出现商业模组和规则书原文。介绍页现有的对局截图
  出自开发库、露出了商业模组内容，已另案处理，本片不复用那批截图。
- **商标**：Chaosium 的粉丝政策原文写明，用户下载、安装、运行的软件、App、VTT 不在政策覆盖范围内，
  也禁止使用其 logo。本片不用 Chaosium 的 logo、美术和模组，片中只做描述性提及，片尾和简介带免责
  声明。项目名「CoC Player」本身的风险由作者另行评估；如果改名，重新录屏、重新渲染即可，不必重录磁带。
- **发布时机**：安装包上线、介绍页下载链接填好之后再发。

## 6. 审片节点

作者只需要在这五处看一眼：

1. 旁白稿和分镜的文字版；
2. 试音：同样几句台词，两三个候选音色各念一遍，挑一个；
3. 故事审核：看一遍磁带对应的对局文字记录，确认故事好不好看、钩子有没有拍到，通过后锁定磁带；
4. 粗剪：完整 2 分钟的低清预览；
5. 终版：4K60 成片、封面和简介。

## 7. 不在本期范围

- 完整实况长视频（调研显示实况录像的播放比宣传片高，以后用同一盘磁带就能出）；
- 竖屏版（小红书、抖音）；
- 场景配图（会引入更多 AI 生成图像和标识要求，第一版先不加）；
- 安装包构建与发布。

## 8. 实施时再定

- 录屏方式：技术验证后在标签页采集和 OBS 之间选一个；
- TTS 引擎与音色：试音后定；
- 录磁带用哪个模型：用候选模型试跑第一幕，对比叙事质量后定；
- 具体配乐曲目：按分段情绪从台账候选里挑。
