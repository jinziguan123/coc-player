# 移动领域边界

日期：2026-10-24。

本轮把移动的个人检定与共同障碍结算，从数据库驱动的流程中抽出。目标是让业务规则能以普通值测试，避免每次修改结算语义都需要准备 ORM 和模型替身。

## 当前职责

| 位置 | 负责什么 |
|---|---|
| `app/domain/movement.py` | 不可变移动意图、检定结果、结算决策；个人通行、共同障碍、重复结果与参与者资格规则 |
| `app/domain/movement_language.py` | 移动原话分类与出口词识别，不读取模组或存档 |
| `app/domain/movement_space.py` | 只读空间快照与出口目的地解析，歧义时返回候选而不擅自选择 |
| `app/application/movement_space.py` | 将模组 JSON 字段投影为不可变快照，避免保留 ORM 或可变 JSON 引用 |
| `app/application/movement_plans.py` | AI `TurnPlan` 到领域 `MovementIntent` 的转换，兼容旧 `scene_change` |
| `app/services/movement.py` | 原有公开入口、导航候选集适配、状态加载、位置资格快照、事务写入和提交后的展示 |

调用方向：原移动服务使用输入转换器取得领域意图，使用领域函数计算结算结果，再执行位置和事件写入。领域只接收角色 ID、状态和结果，不接收 SQLAlchemy Session、ORM 对象、Provider 或事件推送对象。

`settle_check` 不修改传入状态；返回的状态和角色名单以不可变元组承载。执行顺序沿用原提案顺序。参与者是否仍在出发位置由应用服务提供快照，领域规则根据资格集合决定是否允许移动。共享障碍成功时包含先前尝试失败的参与者；个人检定只允许成功者通过。

## 兼容与事务

存档键、状态字符串、接口与重生成策略不变，无需迁移数据库或重新导入模组。模型容错仍由 AI 层负责，领域不重复实现模型输出修复。

原移动服务继续拥有事务：位置、事件、待执行记录和裁定凭据一起提交；广播和配图仍在提交之后。抽取纯规则没有改变事务范围。

## 约束与验证

`test_layering.py` 新增领域依赖禁令，包含函数内导入；领域仅允许标准库及领域模块，禁止通过相对导入越过领域目录。

`test_movement_space.py` 检查多出口歧义、方位选择、别名解析、快照隔离与原话分类。

`test_movement_domain.py` 检查个人/共享结果差异、先失败后成功、离场参与者、全员失败、重复与无关结果，以及规划器转换的兼容性。原 `test_natural_movement.py` 继续验证真实编排、工具入口和数据库事务。

## 尚未迁移

这不是完整的六边形架构迁移。原话分类和空间解析已迁入领域，移动服务仍承担导航适配、角色筛选、裁定编排、ORM 和展示；没有新增通用仓储接口或 Unit of Work 框架。`services` 内原有的循环依赖也尚未全部解除。

后续应按业务收益继续分离角色选择与移动裁定，再明确持久化和输出端口；不应仅为缩小文件而把同一套依赖复制到更多文件。其他模块不应反向引用领域以外的实现来扩展本领域。

## 第二轮：空间解析

空间快照只包含场景 ID、称谓、描述、出口与候选 ID，所有嵌套集合均使用 tuple/frozenset。
构建后修改源模组 JSON 不会改变快照。领域解析只负责判定文字指向哪个目的地，不负责授权移动。
连通图、可通行限制与地点类型仍由现有导航/场景服务提供并校验；没有复制或放宽原有通行规则。

旧的 `movement.analyze`、`movement.scene_terms`、`movement.resolve_destination` 调用入口保留，
原话分类和目的地解析的实现各只有一份。无数据库迁移或存档字段变化。
