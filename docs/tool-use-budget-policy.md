# KP 工具调用与预算策略

更新日期：2026-10-26。

## 当前行为

- KP 静态手册明确：根据当前行动充分使用工具，不为节省调用省略必要步骤；状态变化由工具或兼容指令执行，叙述不能代替执行。
- 保留检定、信息保密、玩家自主权和成功操作不重复的约束。没有给规划器或 NPC 新增其不具备的工具职责。
- rule_lookup / module_lookup 的工具说明不再提前展示次数上限。文本说明与原生 schema 共享工具定义。
- 两类查阅的合计配额、工具循环步数、整轮模型调用/token/时间预算及幂等事务机制保持原有设置；没有提高资源上限。
- 查阅拒绝仍发生在执行器，明确本次未得到新资料，不得编造或声称查询成功。拒绝不是模型已取得证据的回执。
- 工具循环达到步数上限时，框架保留已生成内容与已执行效果，并输出确定性暂停说明；取消原来额外一次无工具生成收尾的请求。暂停说明（`call_budget.TOOL_LOOP_PAUSE_NOTICE`）是**系统事件**而不是 KP 旁白：不并入叙事文本，因此不会被终检或润色改写，下一轮也不会被当成 KP 说过的话；它落库为 `metadata.kind=tool_loop_paused` 的系统事件，并按广播位置排回本轮交错顺序（排在已生成旁白之后），分头时带该组标签。
- 总调用预算耗尽仍由原有异常处理终止生成；各入口统一落库同一条说明（`call_budget.BUDGET_PAUSE_NOTICE`）：已结算结果保留、未执行操作未完成，不承诺重发请求会自动续跑。此前只有常规回合与检定申请给出这条说明，投骰续写、战斗余波、幸运决策、前往与重新生成要么没有提示、要么显示「请重试」；生成管理器的整轮时限提示也改用同一文案。

暂停说明不会推断一份并不存在的待办清单。完成哪些操作以现有事件/工具结果为准，配额耗尽不等于整个行动完成。
本轮没有加入通用重复调用缓存或新的副作用去重机制，继续使用现有配额、循环上限和各业务入口的幂等约束。
工具循环之外的后置守卫仍遵守原有回合总预算，本次未改其生命周期。

## 离线验证

- 实际 build_kp_context 生成的消息经假 Provider 捕获，验证执行职责进入模型上下文，schema 不再显示查阅次数。
- 连续达到工具循环上限时，工具仅执行上限内次数，不出现额外模型收尾请求；已生成内容保留，暂停说明作为系统事件落库、排在旁白之后、不混入旁白（含真实编排与持久化的用例）。
- 回合调用预算硬上限：假 Provider 与真实 Provider 一样在请求前预占，超过次数上限后不再发出请求，已执行的工具效果保留；重新生成等旁路入口在预算耗尽时落库统一暂停说明。
- 拒绝结果回注、查阅硬配额、正常结束和待投骰挂起由工具循环及模组查阅测试覆盖。
- 不使用真实或付费模型，不能据此断言模型使用工具的意愿已经提高。

## 后续对照评测

固定模型、模组、输入、温度与运行时硬预算，比较修改前后：
1. 必要工具遗漏率：有明确必要动作却未调用对应工具。
2. 状态不一致率：叙述宣称完成，但持久化或事件记录不支持。
3. 重复/无效调用率、行动完成率、超限暂停率。
4. 端到端耗时及实际 token/费用。

场景包括陵墓独行与待检定移动、规则查阅、模组信息查询、物品兑现和重复请求。
对修改前后使用相同场景重复采样，保留工具轨迹和数据库快照；调用变多不单独视为成功。
真实模型评测另行确定调用预算，本次不执行。
