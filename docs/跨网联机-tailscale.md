# 跨网联机：用 Tailscale 和不在同一网络的朋友开团

> 适用于房主和玩家不在同一个 Wi-Fi / 局域网的情况。
> 同一局域网内直接看 [README 的「联机」小节](../README.md#联机)，不需要本文。

## 为什么是这条路

本应用**没有账号体系，也没有传输加密**。把后端端口转发到公网，等于让任何扫到这个端口的人
都能读写你的房间、消耗你配置的 AI 额度。`docs/adr/ADR-001-桌面优先与可信局域网边界.md`
明确把「可信网络」作为多人能力的前提。

Tailscale 这类覆盖网络的做法是：在双方之间建一条 WireGuard 加密隧道，给每台设备发一个
`100.x.y.z` 的虚拟内网地址。对本应用而言，朋友从 `100.x.y.z` 连过来和从
`192.168.x.y` 连过来没有任何区别——**它不是"把服务暴露到公网"，而是把可信局域网延伸到广域**。
ADR-001 的前提因此仍然成立。

顺带一提，《杀戮尖塔2》的联机也是同一个思路：它自己不部署服务器，直接用 Steam 的
`ISteamNetworkingSockets`（自带 NAT 穿透，打不通时走 Valve 的中继）。我们蹭的是 Tailscale。

## 准备

- 房主和每位玩家都要装 Tailscale 客户端（Windows / macOS / Linux / iOS / Android 都有）。
- 免费的 Personal 方案够用：**6 个用户、用户设备数不限**（2026 年 4 月改版后的额度）。
- 房主机器要一直开着——它跑着后端、数据库和 AI 调用。

## 步骤

### 一、房主：打开局域网可达

1. 「设置 → 联机」打开「允许局域网加入」；
2. 按提示**重启应用**。监听地址在进程启动时确定，不重启的话后端仍然只绑回环，
   Tailscale 的虚拟网卡同样送不进去。

重启后回到这个面板，它会列出本机地址。局域网地址（`192.168.x.x` 一类）和
Tailscale 地址（`100.x.y.z`）都会出现在这里——本应用已经放行 `100.64.0.0/10`
这个网段（Tailscale 用的是 RFC 6598 共享地址空间，Python 的 `is_private` 不认它，
所以是在 `net_access.py` 里显式放行的）。

### 二、房主：把自己这台机器共享给朋友

**用「共享单台设备」，不要邀请对方加入你的 tailnet。** 两者的区别是权限范围：
邀请进 tailnet 意味着对方能访问你名下所有设备；共享单台设备则只给出这一台。

1. 打开 Tailscale 管理后台的 Machines 页面；
2. 找到跑着游戏的那台机器，点右侧「…」→「Share this machine…」；
3. 生成邀请链接，或用「Share by email」填对方邮箱；
4. 把链接发给朋友。链接是一次性的，**30 天不用就过期**。

对方不需要和你用同一个邮箱注册，用任意 Tailscale 账号接受即可。

有个安全上的额外好处：Tailscale 会自动**隔离（quarantine）**被共享的设备——
它只能响应入站连接，不能主动向对方发起连接。本应用的架构正好只需要
「客人 → 房主」这一个方向（HTTP 提交动作 + SSE 下行），房主的后端从不主动连客人，
所以隔离不会挡任何事，反而白拿一层限制。

### 三、玩家：接受共享并连接

1. 点开邀请链接，用自己的 Tailscale 账号接受；
2. 在自己机器上装并登录 Tailscale，确认连上；
3. 打开 TRPG Player，在「加入房间」处填房主给的地址，形如
   `http://100.x.y.z:8756`；
4. 输入房间码进入。

房主在「设置 → 联机」面板里看到的地址已经带好端口，直接复制发出去即可。

## 连不上时按这个顺序查

1. **房主重启过应用了吗**——只改开关不重启，后端还绑在回环上，这是最常见的原因。
2. **两边 Tailscale 都显示已连接吗**——各自在客户端里确认状态。
3. **房主面板里有没有 `100.x` 开头的地址**——没有说明本机 Tailscale 没起来。
4. **能 ping 通吗**——玩家侧 `ping 100.x.y.z`。通了但网页打不开，说明是端口/防火墙问题，
   查房主机器的系统防火墙是否拦了这个端口。
5. **改用 IP 而不是机器名**——用 `xxx.tailnet.ts.net` 这类名字需要开 MagicDNS，
   直接用 `100.x.y.z` 可以绕开这一层。
6. **两边 tailnet 的 ACL**——默认策略允许共享设备互访；如果任一侧改过自定义策略文件，
   需要确认它没把这条连接挡掉。

## 替代方案与不推荐的做法

- **ZeroTier**：同类方案，思路一样，本应用同样放行它的地址段。按个人习惯选。
- **不要做端口转发**。即使做了，本应用的来源校验也会拒绝来自互联网的请求——
  但那只是兜底，不是可以依赖的防护。
- **不要用 Cloudflare Tunnel / ngrok / frp 之类的隧道**把后端挂上公网。
  体验确实更好（玩家什么都不用装），但那是真·公网暴露，当前版本没有服务端签发的
  身份、没有限流、管理端点也没有按房主收敛。这条路要走得先补安全基线，
  见 `docs/plans/2026-07-27-房间事件分层与跨网联机-design.md` 的 P-Net-3。

## 你需要知道的成本归属

AI 调用发生在**房主机器上**，用的是房主在设置页配的 API key。跨网联机不改变这一点：
玩家越多、跑得越久，账单都记在房主头上。开团前说清楚。
