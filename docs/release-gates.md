# 发布与产品缺口门禁

> 本文记录「不能在代码仓库内完成、必须有外部资源/凭据才能推进」的事项。
> 它们在 README 中仍标为规划中，但已经有明确的完成条件；满足条件前不视为代码缺陷。

## 1. BGM 与音频体验

- **阻塞点**：仓库内没有任何已授权音频素材；BGM 涉及版权，不能从 CDN/第三方站点抓取。
- **决策**：在拿到明确授权的素材前保持静音，不引入来源不明的音频文件。
- **完成条件**：
  1. 选定原创或可商用授权的音乐/环境音素材，并留存许可证与署名清单；
  2. 素材随桌面包本地分发（沿用「离线优先、禁 CDN」约束）；
  3. 实现播放开关、音量、按场景切换与 `prefers-reduced-motion` 同类的降级；
  4. 补充设置页组件测试与打包内容审计记录。

## 2. 桌面签名、公证与自动更新

- **阻塞点**：需要 Apple Developer ID / 公证凭据、Windows 代码签名证书和可复现的 CI secret 管理；
  自动更新还依赖一个签名产物可访问的更新源（endpoint / feed）。
- **完成条件**：
  1. CI 注入签名身份后执行 `codesign` + `notarytool`（macOS）与 `signtool`（Windows）；
  2. `tauri build` 产物通过公证/签名校验并有可复现构建记录；
  3. 配置 Tauri updater，更新清单与安装包走 HTTPS，并有降级/回滚策略；
  4. `docs/packaging.md` 的内容审计清单全部勾选后，才允许对外表述为正式发行版。

## 3. 可安全部署到非可信网络的账号体系

- **阻塞点**：当前威胁模型是「本机 + 可信局域网」，升级为公网 SaaS 需要账号、TLS、持久化
  会话、审计日志和防滥用体系，不是局部补丁能完成。
- **完成条件**：另行立项并先更新 ADR-001/007 的信任边界，再谈实现。

## 4. 完整 CoC 可选子系统

- 当前边界见 [CoC 规则覆盖矩阵](coc-rule-coverage.md)。孤注一掷、幸运消耗、不定性疯狂、
  魔法等尚未确定性实现；在按矩阵的变更纪律补齐前，对外不宣称「完整 CoC 七版」。
