# 后续架构验收（2026-10-25）

## 1. 依赖审计

复跑：`python3 scripts/audit_import_graph.py`。结果存于 `architecture-import-graph.json`。
本轮起点共 224 个模块、961 条显式依赖边，一个 26 模块强连通分量。包含包初始化、局部导入及相对导入；
`from package import submodule` 优先归属真实子模块，避免把无关子模块错误连到包初始化。
不执行模块，不展开动态导入、兼容导出符号的真实归属和父包隐式初始化；静态成环不等于导入失败。
审计器有独立的三节点环、相对/局部导入和包假环回归测试。

证据路径：`ai.context → combat_service → npc_state → ai.context`。
`NpcState.load` 为解析 NPC 的剧情标志状态回调上下文的 `_active_flags/_resolve_state`，
而上下文又依赖战斗服务。这是共享状态解析职责放置不当，尚未在本轮处理。
其余成员见 JSON；不把每个节点都标成独立故障，也不根据分量大小机械拆目录。

优先处理已发现的收益丢失和移动事务一致性，再按收益结算职责拆分大型编排模块；
NPC 状态解析可作为之后独立优化，避免把事务修复扩大成战斗与上下文的全面重构。
