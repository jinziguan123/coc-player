# 移动端到端真实模型验收（2026-10-25）

目的：验证 KP 能否正确响应玩家位置变化。每个场景同时检查玩家原话、规划器原始输出、确定性移动裁定、
数据库位置与事件、发给 KP 的上下文和 KP 最终叙述，并按环节归因。真实模型结果与离线测试分开记录。

## 环境与方法

- 模型：当前激活配置 `deepseek-flash`（OpenAI 兼容协议，reasoning_effort=high，原生工具调用）；
  快模型配置是同一模型的副本。未更换任何模型或配置。文本嵌入为本地 fastembed，不计费；场景配图关闭。
- 隔离：`server/evals/e2e_movement.py` 用 SQLite backup API 把 `server/trpg.db` 只读拷到临时目录，
  所有测试会话建在副本里；AI 配置只读，写入被拦截。验收前后正式存档修改时间不变（10-24 12:55）。
- 驱动：与界面相同的 HTTP 入口（`/chat`、`/advance`、`/roll`、`/luck-decision`、`/regenerate`、`/kp/action`），
  走完整编排（AI 队友 → 规划器 → 确定性裁定 → KP 工具循环 → 终检 → 落库）。
  录制 Provider 记录每次调用的完整输入、输出、工具调用与用量。
- 固定输入：模组《陵墓》；角色克隆自存档中的 4 名调查员；每个场景固定开场旁白与原话；
  骰值钉死（成功 15、失败 95）；村规「燃运」的幸运询问一律按「放弃」处理。
- 结果文件：`server/evals/results/e2e-<时间>/`（已被 gitignore，不入库）。

## 场景结果

| 场景 | 内容 | 结果 | 说明 |
|---|---|---|---|
| s1b | 「我抛下队友，从墙洞钻进去」 | 通过 2/2 | 只有本人（及自己说要跟上的 AI 队友）进前室；KP 按两处分头叙述 |
| s1a | 「我抛下队友，从拱门钻进去」（甬道拱门被封死，措辞本身有歧义） | 修复前 4/6 合理、2/6 失败；补位后 2/2 通过（两次规划器都列出了阿尔文，未触发补位） | 合理：经墙洞进入，或判「拱门封死」受阻并据此叙述；失败见问题 4 |

| s3 | 商量 / 走近观察 / 条件句 | 通过 | 三轮都不移动，KP 未叙述进入；条件句规划器误判为 act，确定性裁定拦住 |

| s5 | 两名真人各自攀爬，一成一败 | 通过 1/1（另 1 次位置正确，但脚本未回应幸运询问） | 只移动成功者，失败者记 failed，KP 分别叙述 |
| s6 | 独行后回来重聚，再一起行动 | 首轮 0/1；修复问题 2 后 1/2；再修问题 3 后 2/2 | 问题 2、3 |

## 发现的问题与处理

1. **留守者被「我们走」带走**（意图识别，已修复）。「我留在甬道守着出口，你们先进去」里，叫别人走的分句被当作
   说话人自己的行动。领域原话分类现在把第二人称主语、且分句里没有第一人称的句子视为叫别人走；
   「你们跟我进去」仍算行动。
2. **去向写在同一句的另一分句里时解析失败**（确定性裁定，已修复）。去向解析只用判为行动的分句：
   「推开东侧拱门前的石板，然后钻进去」只剩「然后钻进去」，在三个出口的前室里判为歧义；
   「从墙洞钻回甬道，回到她身边」因「钻回」不是已知动作，只剩「回到她身边」，判为找不到出口。
   现在行动分句解析不出时退一步用同一句里仍可能描述本人去向的分句（行动、走近、中性），且只采纳能唯一解析的结果；
   补充「钻回/爬回/走回/跑回/折回」。
   **10-26 复核修正**：最初的整句回退会把已排除的否定与别人行动分句带回来——「我不去墓室，我从拱门进去」
   「你们去墓室，我从拱门进去」都被解析成墓室。现在否定、商量、别人的行动与经历分句不进回退，
   这两句在前室判为歧义、请 KP 澄清。
3. **规划器把计划包进外壳，被静默当成空计划**（AI 输出容错，已修复）。34 次规划里 4 次输出
   `{"type":"json_object","decision":{…}}`、`{"action_plan":{…},"narration_brief":…}` 等形状；
   TurnPlan 忽略未知键，得到全默认计划，移动、检定、物品全丢且不留日志（s6 重聚失败的直接原因之一）。
   现在内层承载的计划字段多于外层时拆开使用并记警告。
4. **AI 队友提出别的做法时，规划器漏报真人玩家的移动**（规划器 → 确定性补位，已修复）。修复提示后的 10 次相关回合里
   4 次出现：规划器只列队友的行动或返回空 moves，并写下「本轮以卡里姆的解读宣言为主」这类理由；
   确定性裁定只复核规划器给出的提案，于是玩家明确宣告的移动没有任何裁定，KP 叙述也不回应它。
   经确认改为：规划器对某位真人完全没有提案、而他本人原话是明确行动宣言时，按原话补一条提案，
   照常经证据、去向、可达复核；规划器明确判过的仍以规划器为准。
   配套修正工具守卫：KP 省略 movers 复述已落位的移动时，不再回落搬动没表态的房主与默认跟随的队友。
   **10-26 复核修正**：最初的补位提案没有障碍与检定信息却被当成可直接通行——前室空计划配合
   「我推开东侧拱门前的石板，然后钻进去」会把玩家和默认跟随者直接移进墓室。现在补位提案**永远不直接落位**：
   去向明确且可达时裁定为 `unconfirmed`，不移动、不带跟随者，给 KP 一句必须回应的说明
   （通道无阻就调用 scene_change 让其进入，有阻碍就描写，需要检定就发起）；工具守卫不拦这类裁定。
   原先按计划检定门控补位的做法随之去掉。
   第 5 批真实模型复验（s2 2/2）是在**旧的直接落位行为**下取得的，不能代表修正后的表现；
   修正后的 `unconfirmed` 路径依赖 KP 自己调用 scene_change，尚未用真实模型复验。
5. **规划器同时填 blocked 与 check_skill**（规划器提示，已修复）。修复前 KP 依此发起力量检定，掷出极难成功却叙述
   「石板纹丝不动」。提示现在要求二者二选一：能靠检定通过只填 check_skill，填 blocked 就不再为通过要求检定。
   修复后 3 次都只判受阻、未再要无效检定。

非缺陷：两人攀爬中失败者停在「待检定」是验收脚本没有回应村规「燃运」的幸运询问，补上「放弃」后链路完整。

## 离线回归测试（不调用模型）

- `test_movement_space.py`：第二人称叫人先走不算自己行动、含第一人称仍算、返回动作、整句退路记录。
- `test_movement_adjudication.py`：行动分句歧义时用整句解析；整句也不行时保留原结果；已解析时不看整句。
- `test_natural_movement.py`：s2 留守者不被「我们走」带走；s6 从前室钻回甬道能落位（两例在旧代码上失败）。
- `test_turn_planner.py`：三种外壳形状都能拆出移动提案、外层独有字段补回；正常计划不拆（三例在旧代码上失败）。
- 10-26 复核反例：`test_natural_movement.py` 空计划推石板不绕过障碍、两条整句回退反例；`test_movement_space.py`
  回退分句范围（否定、别人行动与经历、商量不进回退，走近与中性保留）。7 例在 10-25 提交上失败。
- 确定性补位：`test_movement_adjudication.py` 补位范围、已判不补、照常复核且去向明确也不落位；`test_natural_movement.py` 规划器只列 AI 队友、返回空 moves、计划要求检定三例在旧代码上失败，明确判走近、KP 复述移动两例为守护用例。

## 剩余限制

- AI 队友的默认跟随：s2 补位后的一次运行里，卡里姆自己说「在墙洞边停住脚，蹲下去辨读象形文字」，
  仍按「AI 队友默认跟随房主」被带进前室，KP 却叙述他蹲在洞口读字。「停住脚/蹲下去看」没有被识别为留下。
  这条规则在补位前就存在（规划器提案时同样适用），本轮未改。
- 补位提案不带出口与目标，依赖原话里的出口词或地名做唯一解析；解析不出就如实判为歧义或找不到出口。
- 补位后的 `unconfirmed` 需要 KP 自己调用 scene_change 才会移动；KP 若不调用，玩家仍停在原处
  （但有了明确的回应要求），这一点尚无真实模型数据。
- 每个场景只重复 1–6 次（s3、s7、s8 各 1 次），样本小；通过不代表稳定成功，失败率估计误差大。
- s1a 的原话与模组（拱门封死）存在歧义，「经墙洞进入」和「判封死受阻」都按合理处理。
- 叙述质量只按位置一致性人工判读，没有做文笔或节奏评审。
