# ADR-007：管理本机资产的端点仅限本机来源

- 状态：已接受
- 日期：2026-07-27
- 关联：[ADR-001](ADR-001-桌面优先与可信局域网边界.md)（补充，不推翻）

## 背景

ADR-001 把多人能力限定在「可信局域网」，其含义是**相信同一网络里的人不会捣乱**。
实现上，客人模式把整个前端切到房主地址（`localStorage.trpg_server_url`），
于是客人打开的每个页面读写的都是房主的数据。

审计 111 个端点后发现，这条实现路径把「相信朋友不捣乱」悄悄扩大成了别的东西：

- 客人的「设置 → AI 配置」显示的是**房主的**配置，`GET /api/settings/ai/profiles/{id}/key`
  会直接返回**明文 API key**；`PUT` 还能把 `base_url` 改指到任意地址；
- 客人能删除房主的模组、角色、规则书；
- 客人能触发模组解析、配图重生成、RAG 重建、AI 生成角色——全部烧房主的额度。

这些都不需要等到公网暴露才成立，**当前的局域网模式下就成立**。
「可信」应当覆盖「朋友不会恶意删我的库」，不该覆盖「默认把我的 API key 给朋友看」。

## 决策

1. **管理本机资产的端点只接受回环来源**，客人一律 403。范围：
   - AI 配置的全部增删改查（`/api/settings/ai/*`）；
   - 素材库的写操作：角色、模组、规则书的 `POST`/`PUT`/`PATCH`/`DELETE`，
     以及会调用 AI 或写盘的操作（上传、解析、生图、RAG 重建、AI 生成）；
   - 新手团开局（会建会话并调用 AI）。
2. **按请求来源判定，而不是按 token。** `X-Player-Token` 是客户端自造的明文串、
   可以随便伪造；请求来自不来自回环是传输层的事实，伪造不了（除非攻击者已在本机上）。
3. **只收紧「管理」，不收紧「查看」。** 客人仍需读到房间用到的模组与角色，
   相关 `GET` 保持开放。
4. **一个例外：`GET /api/settings/ai/status` 对客人开放。** 客人要判断的正是
   「房主配没配好 AI」（AI 调用发生在房主机器上），锁掉会让客人的开局前置校验永远失败。
   它只返回一个布尔和配置昵称，不含凭据。
5. 前端相应地把管理类页面切到 `localApi`（始终打本机），客人管理的是自己的库。

## 后果

- 客人模式下，设置页与素材库的增删改作用于**客人自己的机器**，这也是更符合直觉的行为。
- 房主的凭据不再随连接暴露；ADR-001 的「可信局域网」回到它本来的含义。
- **已在后续补上**（2026-07-27 同日）：
  - 房间码从 6 位 hex（16 字母表，24 bit）改为 8 位 base32（去掉易混的 I/O/0/1，约 40 bit）；
  - 房间码查询、加入房间加了按来源 IP 的速率限制（slowapi 内存后端，房主本机豁免）。
    注意 slowapi 默认 `key_style="url"`——房间码在路径里，按 URL 计数会让每次猜测各占
    一个计数桶、防枚举完全失效，必须设成 `"endpoint"`（有回归测试盯住这个配置）。

- **仍未解决**（明确留给后续，不要误以为本 ADR 让公网暴露变安全了）：
  - 房内玩家仍可通过正常游戏动作消耗房主的 AI 额度，**没有房间级配额**——
    这需要的是按房间计量，不是按 IP 限速，两者不能互相冒充；
  - `X-Player-Token` 仍是客户端自造的明文串，不是身份认证；而且同一个 token 会发给
    你连过的每一台主机，恶意房主可据此在别的主机上冒充你；
  - 素材库的**读**仍对客人开放，存在信息泄露面；
  - 没有 TLS，局域网内可被旁路嗅探。

  因此 ADR-001 第 3 条依然有效：**当前版本不承诺公网安全，不要把端口暴露到互联网。**
  跨网联机请走覆盖网络，见 [跨网联机文档](../跨网联机-tailscale.md)。
